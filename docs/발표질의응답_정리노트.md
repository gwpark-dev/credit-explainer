## Part 1 — 모델링·평가 관련

### Q1. "현실 분포 홀드아웃 40,092건 + 5-fold OOF"가 무슨 의미인가?

- 원 노트북은 연체자:정상 = 50:50짜리 185건 표본으로 평가 → 실제 연체율 0.23%와 동떨어진 **착시 시험**.
- **현실 분포 홀드아웃** = 전체의 20%(40,092건)를 실제 비율(연체율 0.23%, 양성 92건) 그대로 층화 분할해 봉인한 최종 시험 세트. 모형이 학습 때 본 적 없음.
- **5-fold OOF** = 5조각으로 나눠 "자기가 안 본 조각"에 대한 예측만 모은 것. 실제로는 용도가 다른 **두 번**:
  - **OOF-A (전략 비교·튜닝)**: 전체 데이터 5-fold — "양성 462건 전체 참여"는 여기. 안정적 순위 비교 목적. 비교 모형들은 일회용
  - **OOF-B (보정·임계값)**: 학습셋(80%) 내부 5-fold(양성 370건) — 홀드아웃 완전 미접촉, 누수 없음
- 누수 층위 구분: 최종 모형은 학습셋으로만 학습 + OOF 예측은 항상 '안 본 조각'에 대한 것 → **모형 수준 누수 없음**. 다만 전략 '선택'이 홀드아웃 행 포함 성적을 참조한 점은 엄밀히는 한계 — 방어: 전략 간 격차가 압도적(0.9248 vs 0.8127 vs 0.758)이라 순위가 뒤집힐 여지 없음, 민감한 수치 결정은 전부 OOF-B. 더 보수적 대안 = nested CV(개선 방향으로 언급 가능).
- 역할: **OOF = 모의고사(고르는 용도), 홀드아웃 = 수능(최종 성적표, 딱 1회)**.

> **한 줄 답변**: "보정·임계값은 학습셋 내부 OOF만 써서 홀드아웃과 완전 분리했고, 전략 비교는 안정성을 위해 전체 데이터 OOF를 썼습니다. 최종 모형은 학습셋으로만 학습해 모형 수준 누수는 없으며, 더 보수적으로는 nested CV가 개선 방향입니다."

### Q2. "1:1 언더샘플링 1회로 200,459건 → 924건만 학습"이 무슨 뜻? 왜 데이터를 버렸나?

- 불균형 데이터를 그대로 학습하면 AI가 "전부 정상"으로 찍어도 정답률 99.77% → 연체자 특징을 배울 동기가 없음. 그래서 연체자 462명 전원 + 정상 462명 무작위 = **924건**의 반반 교실을 만든 것(고전적 처방, 취지는 타당).
- 문제는 **'1회'**: 정상 고객 19만 9,535명(99.5%)을 버림 → '정상'의 다양한 모습을 못 배우고, 어떤 462명이 뽑히느냐에 따라 성능이 복불복.
- 개선 = EasyEnsemble: **"한 번만 뽑는 게 문제면 20번 뽑자"** — 매번 다른 정상 462명으로 교실 20개를 만들어 배깅.

> **한 줄 답변**: "1:1 샘플링 자체는 유효하지만 1회면 데이터의 99.5%를 버립니다. 저는 뽑기를 20번 반복해 배깅했습니다."

### Q3. "균형 표본 학습 확률은 실제 PD와 무관(Brier 0.099), 임계값 0.5면 Precision 1.2%"의 의미는?

- 반반 교실에서 자란 모형은 세상이 반반인 줄 알아서 확률을 부풀려 말함 → 순위는 맞아도 **숫자는 못 믿음**.
- **Brier** = (예측확률−실제)²의 평균. 0.099는 "모두에게 0.23%"라고 말하는 바보 예측(0.0023)보다 43배 부정확.
- **임계값 0.5** = 반반 세상의 유물. 현실 분포에 쓰면 경보 5,948건 중 진짜 74건 → **Precision 1.2%**(경보 100번 중 진짜 1번).
- 해결: Platt 보정으로 눈금 교정(Brier 0.0022) → 그 위에서 비용 최적 임계값 0.0443.

> **한 줄 답변**: "순위는 맞아도 확률 눈금이 가짜라서, 보정으로 눈금을 고치고 그 위에서 임계값을 다시 설계했습니다."

### Q4. Platt 확률 보정이 뭔가?

- **고장난 체중계 비유**: 항상 부풀려 표시하지만 순서는 맞는 체중계 → 버리지 말고 "표시값↔실제값 대조표(환산표)"를 만들어 환산.
- 기술적으로: 모형 점수를 입력, 실제 연체 여부를 정답으로 하는 작은 로지스틱 회귀를 뒤에 붙임. 환산표는 **OOF 예측**으로 학습(자기가 공부한 문제를 다시 풀면 과신하므로).
- 단조 변환이라 **순위(AUC·KS)는 그대로**, 확률의 의미만 진짜가 됨 → "4.49%"가 실제로 100명 중 4~5명 연체라는 뜻이 됨. 임계값·설명문 수치 모두 이 보정 위에서 성립.

> **한 줄 답변**: "순위 성능은 그대로 두고 확률 눈금만 현실에 맞게 재조정하는 사후 처리입니다. Brier가 0.099에서 0.0022로 내려갔습니다."

### Q5. 임계값 0.0443은 앞의 4가지 개선을 통해 도출된 값인가?

- **맞음** — 단, "자동으로 나온 값"이 아니라 토대 위에서 계산한 마지막 단계.
- 의존 사슬: 모형(②③)이 점수를 만들고 → 보정(④)이 진짜 확률로 바꾸고 → 누수 없는 환경(①, OOF)에서 → **비용 가정(FN:FP=10:1)을 추가로 넣어** 기대비용 최소 지점을 탐색 = 0.0443.
- 왜 낮아 보이나: 평균 연체율 0.23%의 **19배** 위험 지점이라 전혀 낮지 않음.
- 비용 가정이 바뀌면? 모형 재학습 없이 **임계값만 재산출**하면 됨(보정해 둔 것의 실무 장점).

> **한 줄 답변**: "①~④가 만든 '누수 없는 진짜 확률' 위에서, 비용 가정 10:1을 넣어 기대비용을 최소화한 값입니다."

### Q6. AUC와 ACC는 다른가? KS·Brier·기대비용은 뭔가?

| 지표 | 답하는 질문 | 비고 |
|---|---|---|
| ACC | 커트라인으로 자른 뒤 몇 % 맞췄나 | 불균형에서 착시(전부 정상 찍어도 99.77%) → 미사용 |
| AUC | 위험한 순서대로 줄 세우는 실력 | 연체자·정상 쌍에서 순서 맞출 확률. 커트라인 무관 |
| KS | 연체/정상 두 집단 분포가 얼마나 갈라지나 | 신용평가 실무 표준, 0.5 초과 양호 (우리 0.7355) |
| Brier | 확률 숫자를 액면 그대로 믿어도 되나 | 낮을수록 좋음 (0.099→0.0022) |
| 기대비용 | 이 모형으로 운영하면 비용이 얼마나 드나 | 비즈니스 지표 (6,054→935) |

> **한 줄 답변**: "ACC는 불균형에서 무의미해 쓰지 않았고, 순위는 AUC·KS, 확률의 정직함은 Brier, 비즈니스 영향은 기대비용으로 나눠 봤습니다."

### Q7. 기대비용 935는 935'원'인가?

- **아님** — 화폐 단위 없는 상대적 벌점: 오경보(FP)=1점, 놓친 연체(FN)=10점의 합.
- 원 방식: FP 5,874 + FN 18×10 = **6,054** / 개선: FP 285 + FN 65×10 = **935** → −84.6%.
- 트레이드오프 주의: 개선 모형은 FN이 늘었지만(18→65) FP를 1/20로 줄여 총벌점이 급감 — 10:1 비용 구조에서 합리적 교환. 단가를 곱하면 실금액 환산 가능하나 **비율(−84.6%)은 불변**.

> **한 줄 답변**: "화폐가 아니라 FN=10, FP=1로 가중한 오류 벌점의 합이고, 핵심은 원 방식 대비 84.6% 절감이라는 상대 비교입니다."

## Part 2 — 아키텍처·XAI 관련

### Q8. XAI는 모델인가, 계산된 수치인가?

- XAI는 특정 모델이 아니라 **기법군의 총칭**. 우리가 쓴 SHAP은 **학습 없는 계산 절차** — 이미 학습된 모형의 예측값을 변수별 기여로 분해(협력 게임이론 Shapley Value = "정산 회계사").
- 수학적 성질: 기여도의 합 = 예측값 − 평균 예측값 (가법성) → 어떤 모델의 '의견'이 아니라 합이 맞는 **정산 내역**.
- 대비: Surrogate·LIME은 설명용 보조 모형을 실제로 만드는 부류 → "복제 충실도" 이슈가 있어 SHAP 선택.

> **한 줄 답변**: "SHAP은 별도 모델이 아니라 학습된 모형의 예측을 변수 기여로 분해하는 계산입니다. 기여도 합이 예측값과 일치하는 정산이라 충실도 이슈가 없습니다."

### Q9. 판정 근거 Top 5는 현업 표준인가? 왜 사례마다 다른가?

- **사례마다 다른 것** = Local 설명의 본질이자 목적. Global(모형 전체 중요도)은 모두 동일하지만, Local은 각자의 변수 값에 따라 기여가 다름. 설명요구권은 '나의' 평가에 대한 설명이므로 Local이 필수.
- **"5개"** = 고정 표준이 아닌 설계 선택. 근거: 미국 Adverse Action 관행 — Reg B(ECOA)는 거절 사유 4개 이하 권고, FCRA는 key factors 최대 4개(조회수 포함 시 5개). 소수 제시 = 이해 가능성 + 조작 방지의 균형.

> **한 줄 답변**: "사례마다 다른 건 개인별 설명의 목적 그 자체고, 5개라는 숫자는 미국 거절 통지 관행(4~5개)에 맞춘 설계 선택입니다."

### Q10. 사람마다 특성이 다르니 '다른 기준'을 적용해서 다른 건가? ⚠️ 표현 주의

- **아니다 — 기준(모형·임계값)은 전원에게 동일.** 다른 것은 각자가 들고 오는 '값'.
- 비유: 전교생이 같은 시험지를 봤는데 감점 과목이 학생마다 다른 것 — 채점 기준이 다른 게 아님.
- "다른 기준 적용"이라 말하면 **자의적 심사**로 들려 신용정보법 제22조의4(불합리한 차별 금지)와 충돌하는 인상 → 발표 금지 표현.

> **한 줄 답변**: "기준은 모든 고객에게 동일합니다. 각자의 변수 값이 달라 기여 내역이 다른 것뿐 — 기준이 다른 게 아니라 사정이 다른 겁니다."

### Q11. 그러면 근거 항목은 내가(사람이) 설정한 건가? ⚠️ 표현 주의

- **아니다** — SHAP이 55개 변수 전부의 기여도를 계산해 절대값 큰 순으로 자동 산출. 사람이 정한 건 '상위 5개를 보여준다'는 **틀(규칙)**뿐, **내용**은 계산의 출력.
- 사람이 고르는 구조면 "불리한 이유 숨기기" 시비로 설명의 신뢰가 무너짐. 자동 산출이라 자의성 없이 재현 가능.

> **한 줄 답변**: "항목은 SHAP이 전 변수 기여도를 계산해 자동 산출합니다. 사람이 정한 건 표시 개수 규칙뿐이라 자의성 없이 재현 가능합니다."

## 거버넌스·규제 관련

### Q13. HITL 검토는 누가 했나? 법률 자료 기반인가?

- 정직한 사실: 데모의 검토는 구현 과정에서 AI(Claude Code)가 수행·기록, 사람은 보고 확인 → **발표 전 본인이 3건을 직접 재검토해서 "제가 직접 검토했습니다"를 완성할 것** (10분 소요: 수치 일치 / 금지 문구 / 환각).
- 검토 기준 = 법조문 원문 심사가 아니라 **규제 취지에서 도출한 자체 체크리스트** (수치 일치←신용정보법 36조의2 / 금지 문구←조작 우려 / 절차←GDPR 22조). 실서비스라면 준법감시·법무 검토가 별도 추가 필요.

> **한 줄 답변**: "규제에서 도출한 자체 체크리스트로 3건을 직접 전수 검토했습니다. 법무 검토를 대체하진 않으며 실서비스에선 준법 단계가 추가됩니다."

### Q14. '규제 매핑'은 LLM이 환각 안 하게 만든 장치인가?

- **아님** — 규제 매핑은 "각 계층이 어떤 법적 요구를 이행하는지" 짝지은 **대응표**(컴플라이언스 지도). 소방 도면이 불을 꺼주지 않듯, 매핑 자체는 기능이 아님.
- 환각을 막는 실제 장치는 별도 3종: 역할 분리(번역만) / 프롬프트 제약(입력 외 수치 금지) / HITL 검토.
- 관계: 규제 요구 → (설계 근거) → 방지 장치 → (이행 증명) → 매핑표.

> **한 줄 답변**: "매핑은 환각 방지 기능이 아니라 규제 이행의 대응표이고, 환각 방지는 역할 분리·프롬프트 제약·HITL이라는 별도 장치가 담당합니다."

### Q15. 'GDPR 22조 HITL·가이드라인 7원칙'은 LLM 출력 시점에 적용되나?

- 시점 구분: **생성 중** = 프롬프트 제약이 출력을 조형 / **생성 후·발송 전** = HITL 관문 / **상시** = 모니터링. HITL은 출력을 만드는 장치가 아니라 **거르는 관문**.
- GDPR은 EU법이라 직접 적용 아님 — 그 요건(인간 개입)을 **설계 원칙으로 채택**한 것.
- 가이드라인 7원칙은 전부가 아니라 시스템으로 대응 가능한 것(보조수단성·신뢰성·신의성실·보안성)을 반영. 조직 차원 원칙은 실서비스 과제.

> **한 줄 답변**: "생성 중엔 프롬프트 제약, 생성 후엔 HITL이 작동합니다. GDPR은 직접 적용이 아니라 요건을 설계에 선반영한 것입니다."

### Q16. 가드레일에 걸리면 출력이 수정되나?

- 데모에서는 3건 전부 통과라 실패 경로 **미발동·미구현** — "설계상 절차"로 말할 것.
- 설계: **자동 수정은 절대 없음**(AI가 만든 걸 AI가 승인하면 HITL 붕괴). ① 폐기 후 사유 피드백과 함께 재생성 → **재생성본도 다시 사람 검토** ② 경미하면 검토자가 직접 수정 ③ 반복 실패 시 사전 승인된 표준 문구 폴백. 모든 실패는 로그(프롬프트 개선 + AI Act 이력 추적).

> **한 줄 답변**: "걸린 출력은 자동 수정 없이 폐기·재생성되며 재생성본도 사람 검토를 다시 통과해야 합니다. 이번 3건은 모두 통과해 이 경로는 발동하지 않았습니다."

### Q17. 이중 가드레일 최종 정리 (내 요약 확정본)

> "LLM 출력에는 이중 가드레일을 뒀습니다. 생성 중에는 프롬프트 제약이 출력을 조형하고, 생성 후에는 GDPR 22조의 인간 개입 요건을 반영해 설계한 HITL 검토가 발송 전 관문 역할을 합니다. 실제 3건 모두 통과했고 환각은 0건이었습니다."

## 발표에서 제외된 주제 (공정성 H) — 질문 들어올 때만 사용

발표 범위에서 삭제했지만, 분석은 수행되어 저장소(노트북 01)에 남아 있음.

- **H의 논리**: 차별적 변수는 법으로 입력에서 배제되지만, 대리변수(Proxy)를 통한 우회 학습은 입력 통제로 막을 수도 확인할 수도 없다 → 출력을 집단별로 쪼개 사후 점검(세분화 평가). 격차 발견 ≠ 차별 확정 — **조사 신호** → 원인 조사(실제 위험 차이인가) → 필요시 조치.
- **수행한 분석**: 인구통계 변수 부재로 취약계층 프록시 그룹(3금융권 대출 보유 376명 vs 미보유 39,716명 — 실제 홀드아웃 집계, 지어낸 수치 아님). 거절률 격차 0.314(DP 관점, 커 보임) vs FNR 격차 0.044(EO 관점, 비슷) + 실제 연체율 29배 차이 → 공정성 정의에 따라 결론이 달라짐(COMPAS 구조).
- **'공정성 정의' vs 지표**: DP·EO는 "무엇이 같아야 공정한가"의 정의(개념), 거절률·FPR·FNR은 그걸 재는 측정 지표(도구).
- **프록시 이중 의미 주의**: 문제로서의 대리변수(차별 우회 통로) ≠ 도구로서의 프록시 그룹(취약계층 근사 구분).

> **질문 대응**: "이번 발표는 설명력에 집중했습니다. 다만 그룹별 세분화 평가 분석은 별도로 수행해 저장소에 있으며, 확장 방향으로 보고 있습니다."
