# Credit Explainer 프로젝트 명세서

> 코어 시스템(XAI 설명 파이프라인) + 확장 모듈(공정성 감사) + 10분 발표자료 — 「AI와 신용평가모형」 발표과제(30%)

---

## 왜 이 프로젝트를 만드는가

### 1. 문제 정의

AI 신용평가모형의 도입 확대와 금융소비자 보호 규제 사이에는 구조적인 간극이 있다. 두 문제는 연결되어 있어 하나만 풀어서는 충분치 않다.

- **P1 설명 간극** — 신용정보법 제36조의2는 자동화 신용평가의 결과·주요 기준·기초정보에 대한 설명요구권과 이의제기권을 보장하지만, 현업의 AI 모형(XGBoost 등 트리 앙상블)은 블랙박스라 실제 제공되는 설명은 '부정사유 코드' 수준에 머문다.
- **P2 공정성 간극** — 민감 변수를 제거해도 상관 높은 변수로 우회 학습되는 대리변수(Proxy) 문제 때문에, 변수 제한(Unawareness)만으로는 차별을 차단할 수 없다. 그룹별 세분화 평가 없이는 편향을 사전에 발견하지 못한다(Apple Card 사례).

규제 환경은 이 간극을 방치할 수 없게 만들고 있다: EU AI Act('26.8월 시행)는 신용평가를 고위험 AI로 분류하고, AI 기본법('26.1월 시행)은 고영향 AI 사업자에게 안전성·신뢰성 확보 의무를 부과한다.

### 2. 기존 접근의 한계

- **전통 스코어카드(로지스틱 회귀)**: 설명력은 높지만 변별력·예측력이 AI 모형 대비 낮다. 성능을 포기하는 방식의 해결.
- **현업 XAI 활용(NICE·KCB·카카오뱅크)**: SHAP 등을 이미 활용하나 주로 내부 검증·부정사유 코드 생성용이다. 소비자가 읽을 수 있는 자연어 설명, 개선 방향 안내, 공정성 감사까지 통합한 형태는 아니다.
- **생성형 AI 단독 활용**: LLM에게 평가 자체를 맡기면 환각·일관성·규제 리스크가 발생한다. 평가와 설명의 역할 분리가 필요하다.

### 3. 해결 방식

역할을 분리한 3단 결합 구조로 해결한다. **판단형 AI는 평가만, XAI는 근거 산출만, 생성형 AI는 번역만** 담당한다(2주차 AI 분류체계의 응용). 그 위에 공정성 감사 모듈을 얹어 P1(설명)과 P2(공정성)를 하나의 '신뢰 계층(Trust Layer)'으로 통합한다.

새 모형을 만들지 않는다. 이미 완성한 실습과제 모형(EasyEnsemble 20×HGB, AUC 0.9247)을 그대로 코어로 사용하고, 그 위에 빠져 있는 신뢰 계층을 더하는 구조다. 실습과제(20%)와 발표과제(30%)가 하나의 스토리로 연결된다.

### 4. 차별화 포인트

- **차별화 A — 역할 분리 아키텍처**: 생성형 AI를 평가에서 배제하고 설명 '번역'에만 한정하여, 8주차에서 배운 환각·신용조작 우려에 대한 방어 논리를 구조 자체에 내장.
- **차별화 B — 설명 + 공정성 통합**: 개인 단위 설명(SHAP Local·Counterfactual)과 그룹 단위 감사(공정성 3기준)를 한 파이프라인에서 제공. 8주차의 두 축을 모두 커버.
- **차별화 C — 자체 실험 근거 보유**: 신용사면 시뮬레이션(연체기록 삭제 실험)으로 "변수를 지워도 모형은 우회 학습한다(AUC 0.9247→0.9240, 저하 없음)"를 직접 실증. 대리변수 문제와 사후 감사 필요성의 근거로 Q&A·부록에 활용.

## 프로젝트 개요

### 한 줄 정의

기존 신용평가모형 위에 SHAP 기반 근거 산출과 LLM 자연어 설명, 공정성 감사를 얹어 신용정보법 설명요구권에 대응하는 '신뢰 계층' 서비스 — 작동하는 데모와 10분 발표자료로 완성한다.

### 프로젝트 목적

- **설명요구권 대응 파이프라인 시연** — 점수 산출 → SHAP 근거 → 소비자 눈높이 자연어 설명문 자동 생성의 전 과정을 실제 데이터(AI Play DB)로 시연
- **공정성 감사 체계 시연** — 그룹별 Demographic Parity·Equal Opportunity 지표 산출과 대리변수 탐지
- **발표 완성** — 10주차 10분 발표(과제 30%)에서 "문제 정의 → 배운 내용 → 해법 → 데모 → 한계"의 완결된 스토리 전달

### 시스템 설계 원칙

- **역할 분리** — 평가(판단형)·근거(XAI)·번역(생성형)·통제(거버넌스)의 계층 분리, 계층 간 침범 금지
- **기존 자산 재사용** — 실습과제 모형·데이터를 그대로 코어로 사용, 새 모형 개발 없음
- **규제 정합성** — 각 구성요소를 신용정보법·EU GDPR(HITL)·금융 AI 가이드라인 조항에 명시적으로 매핑
- **발표 우선** — 모든 산출물은 10분 발표에서 보여줄 수 있는 형태(화면·차트·수치)로 제작

### 전체 시스템 아키텍처

```
[평가 요청]
     ↓
[① 판단형 AI 계층]  EasyEnsemble 20×HGB + Platt 보정 (실습과제 모형 재사용)
     ↓               → PD 산출 → 신용점수
[② XAI 계층]        SHAP Local (개인별 상승/하락 요인 Top 5)
     ↓               Counterfactual (개선 시뮬레이션)
[③ 생성형 AI 계층]   LLM: SHAP 결과 → 자연어 설명문 "번역"
     ↓               (템플릿 제약 · 프롬프트 5요소 · 평가 비관여)
[④ 거버넌스 계층]    HITL 검토(GDPR 22조) · 공정성 감사(3기준 + 대리변수 탐지)
                     · 금융 AI 가이드라인 7대 원칙 매핑
```

## Phase 1: 코어 데모 — XAI 설명 파이프라인 + 공정성 감사

### 개요

실습과제 노트북을 확장하여 ①~④ 계층이 실제로 작동하는 데모 노트북을 완성한다. 단독으로도 발표 가능한 결과물.

### 핵심 작업

| 구분 | 내용 |
|---|---|
| SHAP 분석 | 홀드아웃 개인별 SHAP Local 값 산출, 대표 사례 2~3건(승인/거절/경계) 선정 |
| Counterfactual | "어떤 변수를 얼마나 바꾸면 몇 점 개선" 시뮬레이션 |
| 설명문 생성 | SHAP 결과 → LLM 자연어 설명문 (템플릿 제약 프롬프트, 특강 5요소 공식 적용) |
| 공정성 감사 | 그룹(연령대 등) 구분 후 승인율·오분류율 격차 산출(공정성 3기준), 대리변수 상관 분석 |
| 부록 실험 | 신용사면 시뮬레이션 결과 차트화 (완료된 실험의 정리) |

### Phase 1 결과물

- 작동하는 데모 노트북 (설명문 생성 실행 화면 포함)
- 발표용 캡처·차트 (SHAP 요인 차트, 공정성 지표 비교, 사면 실험 결과)

**단독으로도 발표 가능한 결과물.**

## Phase 2: 발표자료 — 10분 PPT + Q&A 대비

### 개요

Phase 1 산출물을 기획서의 10분 구성안에 따라 발표자료로 조립한다.

### 슬라이드 구성 (10~12장)

| 시간 | 슬라이드 | 내용 |
|---|---|---|
| 0~1분 | 도입 | "대출 거절. 사유: 신용평점 미달. 끝." — 문제 제기 |
| 1~3분 | 문제 정의 | 성능 vs 설명(4·8주차) × 규제 요구(9주차) = 간극 |
| 3~6분 | 해법 | 4계층 아키텍처, 역할 분리 논리 (2주차 분류체계 응용) |
| 6~8분 | 데모 | 설명문 생성 화면 + 공정성 감사 결과 |
| 8~9분 | 한계와 통제 | 환각·신용조작 우려와 대응(템플릿·HITL) |
| 9~10분 | 마무리 | "AI 도입의 이유는 성능만이 아니라 신뢰다" (1주차 수미상관) |
| 부록 | Q&A 카드 | 사면 실험(대리변수 실증), 기존 서비스와의 차별점, 책임 소재 |

### Phase 2 결과물

- 발표 PPT (발표자 노트 포함)
- 예상 질문·답변 목록

## 진행 원칙 및 일정

**Phase 단계별 엄수**: Phase 1(데모) 완성 → 발표에 쓸 화면·수치 확정 → Phase 2(PPT) 착수. 데모 없이 슬라이드부터 만들지 않는다.

| 단계 | 작업 | 일정 (발표: 10주차 수업) |
|---|---|---|
| 완료 | 강의자료 학습, 아이디어 기획서, 사면 시뮬레이션(방향 검증) | ~7/27 |
| Phase 1 | 데모 노트북 (SHAP·설명문·공정성 감사) | 7/27~7/28 |
| Phase 2 | 발표 PPT + Q&A 대비 | 7/29~7/30 |
| 버퍼 | 리허설(10분 타임 체크), 수정 | 발표 전일 |

### 범위 제외 (Out of Scope)

실서비스 배포(웹/앱), 실제 고객 데이터 연동, LLM 파인튜닝, 모형 재개발은 본 명세서 범위에 포함되지 않는다. 데모는 "발표장에서 실행 화면을 보여줄 수 있는 노트북" 수준을 목표로 한다.

## 기대 효과 (수업 내용과의 매핑)

- **도메인 측면** — 1주차 프레임(문제 정의 → AI는 수단) 그대로 실행한 사례. 실습(20%)과 발표(30%)의 단일 스토리 연결.
- **방법론 측면** — 4주차 AI 방법론(트리 앙상블) + 8주차 XAI(SHAP·Counterfactual)의 실전 적용.
- **규제 측면** — 9주차 신용정보법·GDPR·EU AI Act·금융 AI 가이드라인을 아키텍처 구성요소에 1:1 매핑.
- **생산성 측면** — 특강의 프롬프트 5요소·역할 분리(표준화=자동화, 판단=인간)를 설명문 생성 설계에 반영.
