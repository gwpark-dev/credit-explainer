# 0001. 생성형 AI 계층(설명문 생성)의 구현 방식

- **Status**: Accepted
- **Date**: 2026-07-27

## 배경 (Context)

프로젝트명세서(§전체 시스템 아키텍처)는 ③ 생성형 AI 계층이 "SHAP 결과를 소비자 눈높이의 자연어 설명문으로 번역"한다고 정의하지만, 어떤 LLM을 어떤 방식으로 호출할지는 정하지 않았다. 이 선택은 API 키 관리(보안), 비용, 발표장 시연 환경(네트워크), 그리고 "생성형 AI를 실제로 활용했는가"라는 발표 주장의 정합성에 영향을 준다. 발표는 10주차 수업(10분)이며, 발표장 네트워크는 보장되지 않는다.

## 대안 검토 (Alternatives)

| 대안 | 장점 | 단점 / trade-off |
|---|---|---|
| **A. Anthropic Claude API 호출** | 실제 생성형 AI 시연으로 발표 주장과 구현이 일치. 한국어 설명 품질 최고. 구현 단순(REST 호출) | API 키 관리 필요(.env + Bitwarden), 소액 비용 발생(데모 규모 $1 미만 추정), 발표장 네트워크 의존 |
| B. 로컬 LLM (Ollama) | 무료, 오프라인 시연 가능 | 설치·모델 다운로드 부담, 한국어 금융 설명 품질 편차 큼, WSL2 리소스 부담 |
| C. 템플릿 문장 조립 (LLM 미사용) | 리스크 0, 오프라인, 출력 완전 통제 | "생성형 AI 계층"이라는 아키텍처 주장이 약해져 발표 정합성 훼손 |

대안 비교는 실측이 아닌 정성 평가로 수행했다(품질 실측은 Phase 1 산출물이 나온 뒤에야 가능하며, 결정 지연 비용이 더 크다고 판단).

## 결정 (Decision)

**대안 A를 주력으로 채택하고, C의 요소를 폴백으로 흡수한다.**

1. 설명문 생성은 Anthropic Claude API를 호출해 수행한다. 프롬프트는 특강의 5요소 공식(역할·맥락·목표·형식·제약)을 따르고, 설명 템플릿 제약(허용 변수 목록·수치 근거 필수·투자권유 및 점수조작 유도 문구 금지)을 시스템 프롬프트에 포함한다.
2. **발표용 캐시 모드를 필수 구현한다**: 대표 사례 3건의 생성 결과를 JSON으로 저장(`outputs/explanations_cache.json`)하고, 노트북은 `USE_CACHE=True`일 때 API 호출 없이 캐시를 재생한다. 발표장 기본 모드는 캐시, 네트워크 확인 시 라이브 시연.
3. API 키는 `.env`(로컬)로만 주입하고 Bitwarden에 원본 보관. `.env`는 `.gitignore`에 포함(코드·커밋·대화 노출 금지).
4. 모델 버전은 구현 시점에 확인해 코드 상수로 고정하고(재현성), 사용 모델명·호출 파라미터를 노트북에 기록한다.

## 영향 (Consequences)

- 발표 자료에서 "판단형 AI + XAI + 생성형 AI 3단 결합"을 실제 작동 화면으로 주장할 수 있다.
- API 비용 상한은 지침 기본값 $5를 적용한다. 초과 예상 시 Claude Code는 멈추고 보고한다.
- ⚠️ 발표장 네트워크 불가 시 라이브 생성 시연은 불가 — 캐시 재생으로 대체(2항으로 완화, 리허설 시 캐시 모드 점검 필요).
- ⚠️ LLM 환각 리스크는 잔존 — 템플릿 제약 + 발표 자료의 '한계와 통제' 슬라이드(HITL)에서 정면으로 다룬다.
- 실제 모델명·요금은 구현 시점 확인 사항이며, 확인 결과가 본 결정의 전제(소액 비용)와 크게 다르면 재검토한다.
